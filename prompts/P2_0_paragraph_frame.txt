# 【Stage 2 共用】论证链条（可选用标签，非固定模板）

## 核心原则
- **结构不固定**：论点、论述、支撑、举例、总结/扣题等只是**拆解用户原文时可选用的标签**，不是每段都必须凑齐的清单。
- **判定标准只有一个**：这段（或两个分论点）能否形成**可理解的完整论证**——读者能跟上「观点 → 为什么成立 → 有何依据/例证 →（如有）收束」。
- **先拆解、再评判**：用户输入一团乱麻时，先用下方标签**识别已有部分**；`slots` 里**只填识别到的内容**，未出现的维度保持 `null`，**不要**为未使用的维度列入 `missing`。
- **论点≠论述**：不能把 claim 换词再说一遍当论证；若全文只有重复观点，verdict=fail。

## 可选用标签（按需选用，非全填）
| 标签 | 常见含义 |
|------|----------|
| claim | 论点 / 分论点 |
| reason | 原因 / 为什么 |
| elaboration | 论述展开 / 机制 / 如何起作用 |
| support | 支撑 / 证据类型 |
| example | 举例 / 具体情境 |
| link | 扣题 / 段内小结 / 总结 |

同一信息只归一个最贴切的标签；example 与 support 可只出现其一。

## Pass / Fail（整体论证，非 checklist）
**Pass**（Body 段）当且仅当：
- 论点清晰，且与 Stage1 立场一致；
- 除论点外，至少有一层**实质性**论证信息（原因、机制、支撑或举例等，组合方式不限）；
- 无明显逻辑断裂、跳跃或与 Body 另一段同义重复。

**Fail** 仅当：
- 论点不清 / 与立场矛盾 / 与 Body 另一段重复维度；
- 或论证实质为空（只有口号、只有重复论点）；
- 或读者无法串起因果/说理链。

`missing`：**只列**「若不补则论证仍不完整」的维度（通常 1–2 项），用自然语言说明缺什么功能（如「缺：为什么成立」），**禁止**把未使用的可选标签一律列入 missing。

## logicBreakdown（有实质用户输入时必填）
```json
"logicBreakdown": {
  "target": "subpoints" | "body1" | "body2",
  "chainSummary": "一句话概括当前论证链是否闭环",
  "slots": { "claim": "仅填识别到的", "reason": null, ... },
  "missing": [],
  "userBlobSummary": "可选：如何归类用户原文"
}
```
- `slots`：只填有内容的键；其余 null。
- 所有字符串单行，勿含未转义双引号。
